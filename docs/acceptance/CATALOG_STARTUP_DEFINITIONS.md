# Catalog startup definition placement

## Acceptance criteria

- SD-001: Startup inspection identifies literal declaration names, not matching words in declaration values, flags, comments, prompt strings, or quoted text. Real declarations after the catalog insertion point remain blocked. Diagnostics identify the startup file and source line with fixed guidance, without printing source contents.
- SD-002: An earlier literal startup alias can remain when the planned native source provides a reviewed authoritative alias of the same name before the catalog overlay. Preserve all earlier startup bytes. Do not silently take ownership of an unrelated startup name, permit an early alias to mask a native function fallback, or treat a deferred function-body definition as an immediate declaration.
- SD-003: Startup inspection preserves original line and byte coordinates when masking known interactive-shell guards or owned blocks. Insert the generation loader after the complete proven native source statement or file-existence guard. Never insert inside a guard or before its native source because analysis removed lines.
- SD-004: Existing source-route safety remains intact: duplicates, dynamic or unproven native routes, ambiguous control flow, later overriding declarations, and modified owned blocks block automatic application. Immediate opaque eval requires explicit placement, including command-prefix and list forms; a deferred function-body eval remains deferred. Explicitly unsupported cases must identify the placement problem without claiming arbitrary startup programs are understood.
- SD-005: Synthetic Bash and Zsh inspection tests cover early covered aliases, uncovered aliases, native function masking, quoted-value false matches, real late definitions, conditionals, deferred functions, multiline strings, source routes, and original-coordinate preservation. Compiled Bash PTYs at narrow and wide widths include a standard interactive guard and earlier defaults, verify new-shell catalog dispatch and fallback preservation, and restore exact native/startup bytes offline.
- SD-006: A private full read-only application-plan preflight checks the affected setup before reporting it ready to retry. Proposed review records remain in memory and cannot be saved or applied by this diagnostic. No real source enters fixtures, is executed by inspection, or is changed by tests.
- SD-007: Explicit startup-file enrollment may propose placement at the end of that file when other static literal startup loads prevent automatic placement. Move only a single proven native source statement or guard, preserving its exact bytes and sourcing native fallbacks once, immediately before the catalog overlay. Preserve other startup bytes and explain the relocation and unproven earlier loads in the final plan. Do not execute or claim to understand those loads. Dynamic or duplicate native routes, unproven declaration boundaries, and unsupported immediate exit paths remain blocked. The user confirms the exact plan before application; inspection grants no approval or ownership.
- SD-008: Explicit relocation disables alias expansion using separate parsed statements before sourcing native definitions and evaluating the overlay, then restores the prior option state on success and helper failure. Unknown aliases from earlier opaque loads cannot rewrite retained function headers or bodies. Preserve the external alias table; do not claim unknown external functions or source behavior were inspected. Known immediate handoff-control declarations remain refused. Re-enable retains the enrolled placement and exact moved source block under the installed startup identity proof.
- SD-009: Explicit enrollment can preserve a static existence-guarded opaque load written as `[ -f|-s OPERAND ] && source OPERAND` or its escaped-dot form, with an optional trailing comment. Match both operands after bounded literal decoding. Directory-variable operands require a preceding proven top-level scalar assignment from an absolute literal or HOME-relative literal; no shell evaluation, command substitution, indirect expansion, arrays, or environment lookup supplies the value. Reject visible reassignment ambiguity, native-file referents, wrong-shell sources, dynamic operands, and extra commands. Preserve all original bytes. Loaded files remain trusted opaque user configuration, including their effects on shell variables; inspection does not claim to establish their runtime behavior.

## Review gate

Medium implementation, independent high review, medium corrections, and repeated high review must close actionable findings. Run make fmt check. Unavailable Zsh and platform runtime evidence stays explicit.
