# Catalog transaction contract

Workflow manifest version 2 is separate from the existing private-file manifest version 1. Version 1 journals remain readable and recoverable through their existing API. Unsupported workflow versions are rejected without migration.

A workflow snapshot has exactly `manifest` and `progress`. The manifest has `version`, `spec`, and `actions`. The spec has `operation_id`, `state_root`, `private_roots`, and `targets`. Every target names `path`, `role`, `expected`, `mode`, and `recovery_order`; optional fields are `remove`, `expected_link`, `preserve_symlink`, and `promotion_source` and `directory`; `promotion_expected` pins the reviewed source directory identity. Planned bytes are never serialized. Each action contains `target`, `resolved_path`, `parent_identity`, `temporary_name`, `planned_sha256`, `promotion_identity`, and optional `link` and `backup_path`. Identity fields retain the existing FileIdentity encoding: existence, platform identity, size, mode, owner, group, links, and SHA-256. Private roots are explicit absolute mode 0700 directories owned by the current user. User and repository roles authorize only their exact named targets; they do not enroll their parent or home directory.

Journal framing is one unsigned 64-bit big-endian payload length, Go encoding/json compact object bytes in declaration field order, and the 32-byte SHA-256 of that payload. Decoders require byte-canonical JSON and nonnull required arrays; reject missing, duplicate, case-variant, and unknown fields, trailing JSON, incomplete snapshots, wrong root bindings, invalid target bindings, and checksums. Limits are 20,000 actions, 8 MiB per file, 32 MiB per snapshot, and 256 MiB per promoted tree, 100,000 tree entries, and depth 64. Operation IDs contain at most 128 ASCII letters, digits, hyphens, or underscores and start with a letter or digit.

Target parent identities are captured during planning. For a parent created by a named directory action, its identity is captured and durably added before its first child mutation. Directory creation is an explicit target action; recovery removes only empty directories, deepest first after their file targets.

Snapshots reside in `state_root/workflows/operation_id.workflow`, mode 0600. Updates create and sync a target-local `.next` file, atomically rename it over the prior snapshot, and sync the parent directory. Private inverse bytes reside in `state_root/workflows/operation_id-index.backup`, mode 0600. Backups remain after completion. The initial snapshot precedes backups and all live mutations. All existing-target backups are durable before the first live mutation. Replacement temporary files reside beside their target and have deterministic operation-owned names. Snapshot progress records have `stage` and zero-based `target`, plus `identity` for durable target and inverse completion; transaction-wide records use target -1.

Forward durable stages are `backup_synced`, `target_synced`, and `committed`. Recovery durable stages are `recovery_started`, `recovery_target_synced`, and `recovered`. Test hooks additionally observe manifest sync, temporary sync, before and after forward rename, recovery temporary sync, and recovery rename. A failed or killed workflow retains its snapshot. Committed snapshots require cleanup only. Other snapshots roll back in ascending `recovery_order`: callers assign native 0, pointer 1, startup 2, and installed state 3. Restored files are recognized by original content and metadata rather than their replaced inode, so another crash after inverse rename can be recovered again. Once an inverse identity has been durably recorded, recovery requires that exact resulting identity and refuses an externally replaced file. Durable stages follow their legal forward or recovery order, including transaction-wide target -1 requirements.

Every target parent component is opened with no-follow directory descriptors. Mutation uses descriptor-relative creation, removal, and rename. Parent identity, reviewed content, leaf identity, hard-link count, owner, group, and mode are checked. Named user leaf symlinks may be explicitly preserved: only one leaf link is resolved, its exact text and resolved destination are pinned, and the referent is replaced while the link remains. Parent links and chained leaf links are rejected. Hard-linked files and special files are rejected. Existing owner, group, and permissions are preserved; set-ID/sticky modes and extended attributes, including ACLs, cause refusal when their preservation cannot be guaranteed.

Directory promotion names a private staged source and an absent exact destination. Both parents must satisfy descriptor safety. Promotion is a same-filesystem rename with both directories synced; cross-filesystem copying is forbidden. The bounded descriptor-traversed tree hash uses length-framed JSON records of names, content hashes, and metadata. Invalid UTF-8 names, links, special files, unpreservable metadata, and directory changes during inspection are refused. The tree hash and source inode bind promotion and inverse rename. Recovery moves the tree back only when it still matches and the staged source is absent. Changes to a promoted tree block recovery. No recursive deletion occurs.

The transaction API does not acquire a lock. Its caller holds the shared state-directory mutation session throughout planning freshness validation, recovery, application, and cleanup. Journal reading is observational and acquires no lock, writes no files, and performs no recovery.

Acceptance evidence must include replacement/removal and multi-role error boundaries, process death after rename, process death during inverse rename, another recovery after completed inverse mutation, stale target refusal, parent symlink refusal, leaf-link preservation, hard-link and extended metadata refusal, recovery priority, same-filesystem directory promotion, and changed promotion refusal. All fixtures use disposable roots.

## Managed writer acceptance

Configuration updates re-read the current configuration under the shared state-directory session. A saved value derived from an earlier read applies only its changed fields to the fresh value; conflicting concurrent edits are refused. Nested writers accept an explicit session and never acquire a second lock. Context associations use that same lock, replacing the obsolete independent contexts lock. Theme selection, tour state, usage append/clear, and revision clear also cooperate with the state lock. Existing private files and directories with symlinks, hard links, wrong owner/mode, or unsupported extended metadata cause refusal. Revision clearing enumerates only the named private revisions directory and never recursively follows links. Config/state/data directory infrastructure is created only at its fixed known private paths; target subdirectories are named transaction actions. Read-only data-path reporting performs no recovery or mutation. Tracking rejects native files enrolled as catalog fallbacks through the lifecycle safety guard.

Evidence includes concurrent independent configuration fields, conflicting edits, private metadata/link refusal, context lock contention, usage append versus clear, safe revision-directory enumeration, and existing CLI/PTY tests with disposable homes.

A real command subprocess must refuse managed mutations while another process holds the state mutation lock. The contention matrix covers legacy native editing, setup, catalog application, config, theme, context, usage, completion, tracked-file changes, and automatic-sync configuration. Each attempt must leave the disposable home's paths, modes, bytes, and link identities unchanged. Data-path reporting includes installation, ownership, rollback, semantic-sync/push intent, conflicts, stage intents, private clone roots, and managed catalog repositories without creating them.

User targets may carry `expected_link`, an optional exact reviewed leaf link string. A nonempty value requires symlink preservation and must match the resolved link before backups or mutation; the saved action link must match it. Plan targets retain the reviewed symlink identity separately from the hidden referent identity, and freshness checks pin both. Retargeting after a preview must refuse the operation.

Status combines old private journals with strict workflow-v2 journals and canonical pinned clone-stage intents. Inspection takes no lock, performs no recovery, creates no paths, and calls no providers or shell validators. Valid pending records require recovery; malformed or replaced stage roots block it. Filesystem inventories before and after inspection must match.

Automatic sync can be enabled with a catalog enrollment and no legacy repository. Each cycle re-reads configuration under the mutation session, validates tracked-file policy before changing any unit, reconciles enrolled catalog data, and reconciles native aliases only when the configured shell remains legacy and has a legacy repository. Unrelated tracked units retain their behavior; stale tracked catalog fallbacks cause an actionable refusal before any unit writes. Watch-once uses only the shared mutation lock. Daemon deduplication uses a separate persistent OS advisory `watch-worker.lock`, acquired while holding a mutation session and released by process exit; timestamps never authorize takeover or deletion. State path calculation is observational. Tracked replacements preserve metadata through an exact user target with a private backup. Missing user parent directories are refused. Evidence covers catalog-only enable/watch, mixed shell units, stale fallback tracking, daemon lock age independence, and subprocess contention without writes.

Legacy automatic sync resolves the local native file through the configured shell adapter, independently of the invoking shell environment. A configured Bash unit invoked from Zsh must compare only Bash bytes; the Zsh fallback remains unchanged. Worker lifetime locks appear in observational data-path output beside mutation locks. The transaction implementation is divided into coordinator, target/forward write, journal/progress, and inverse/cleanup modules; this division moves reviewed function bodies without changing contracts or behavior.
