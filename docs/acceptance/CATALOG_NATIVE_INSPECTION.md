# Retained native function inspection

## Acceptance criteria

- NI-001: Installing reviewed catalog entries can coexist with unrelated native functions containing ordinary command substitutions and braced parameter expansions. A read-only bounded structural inspection proves each complete declaration boundary without executing or importing the function. Catalog import, approval, and generated declaration grammar remain unchanged.
- NI-002: Retained functions stay byte-for-byte native and receive no approval or ownership implicitly. Their names participate in collision detection. Ambiguous alias dependencies between retained functions and generated declarations still block installation.
- NI-003: Handoff control masking, dynamic top-level definitions, unsafe or unproven boundaries, declaration tails or redirections, malformed substitutions, unsupported constructs, and source bounds remain rejected. Literal comments and quoted strings cannot impersonate a top-level definition or an owned integration block. Errors identify source line ranges and a fixed reason without printing private source.
- NI-003a: Reject unproven control blocks and command lists, including unfinished conditions, dangling operators, and continuations that form unsupported heredoc or substitution operators. Retain unquoted continuations only when horizontal whitespace immediately before the escape and after its newline proves that no tokens are joined. Bound total integration-boundary proof work as well as source size, declaration count, and nesting depth.
- NI-004: Planning, native ownership review, activation, fallback refresh, and the read-only startup helper use consistent native boundary observations. The startup helper executes no validator subprocess. Existing immutable generation, native-input identity, rollback, and exact approval contracts remain intact.
- NI-004a: Recognize a narrowly specified literal Alias Lens shell-init invocation for the selected shell as an owned legacy integration route. Relocate it through the displayed plan into the pinned startup integration and retain its exact original bytes in rollback. Never evaluate it during inspection. Changed commands, command tails, dynamic shell arguments, wrong-shell invocations, and invocations hidden inside functions, quotes, or control flow must never be recognized or removed as owned routes. Unproven top-level routes and duplicate integration routes block installation. Proven retained functions containing the invocation remain native.
- NI-005: Synthetic parser tests cover nested substitutions, parameter expansion, quotes, fake closing braces, continuations, unclosed constructs, reserved names, dynamic definitions, collisions, dependencies, and integration boundaries. Actual compiled Bash PTYs at narrow and wide widths install a batch alongside retained helpers, execute an installed synthetic alias and a helper in a new shell, and verify exact preserved fallback bytes. Inspection sentinels must never run.

## Review gate

Medium implementation, separate high review, medium corrections, and repeated high review must close actionable findings. Run make fmt check. Keep unavailable Zsh and platform runtime evidence explicit. Real user files may be inspected privately for diagnosis but must never enter fixtures or logs, be executed by diagnostics, or be changed by tests.
