# Catalog persistence acceptance

Approval format 2 records contain key and approved_at. Keys contain entry_id, shell, name, kind, implementation_sha256 and renderer. Implementation SHA keeps renderer v1's length-framed kind, implementation field and implementation bytes hash; renderer and name are independently bound in the key. Approval timestamps must be canonical UTC RFC3339Nano.

Installed format 1 contains records with shell, generation_id and renderer. Optional records bind native input SHA, startup graph SHA, startup records and rollback ID. Startup records bind an absolute path and SHA, optional original absolute path and SHA, and optional route.

Ownership format 1 records bind ID, shell, name, kind, absolute source path, byte start and end, exact definition and its SHA, reviewed full source SHA, immutable original absolute path and SHA. Rollback format 1 binds ID, shell, timestamp, native absolute path, immutable original absolute path and SHA, and startup records. Ranges must be nonempty and nonoverlapping.

Generation format 1 contains ID, shell, renderer, platform, absolute native path, native policy, source SHA, native-input SHA, complete output SHA, profiles, entries, included IDs, confirmations, and executable resolutions. Policy is regular-user, with the adapter resolving explicitly enrolled symlinks before construction. Entries bind the full catalog entry and exact emitted declaration. Resolutions bind entry ID, program and absolute executable path. Lists are sorted deterministically by profile, entry name then ID, approval tuple and executable entry ID. Included IDs follow entry order. Duplicate records are rejected. No timestamp or temporary path enters identity. An enrolled source symlink's identity is included to detect retargeting even when its old referent remains unchanged.

Identity hashes a uint64 big-endian byte-length frame followed by canonical compact JSON of the manifest with empty ID and empty full-file SHA. Complete output SHA hashes every output byte separately. SHA-256 of empty bytes is e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855. The pointer is exactly 64 lowercase hex bytes followed by LF; its empty-body SHA example is that value plus LF. CRLF, extra LF, truncation and trailing bytes fail.

All codecs reject unknown or duplicate JSON fields, null, trailing data, nesting beyond 40, missing required fields, unsupported versions, noncanonical hashes, invalid timestamps, unsafe names and invalid shell/renderer combinations. Documents are capped at 8 MiB and record lists at 10000. Private reads require a regular mode-0600-equivalent file, bounded bytes and stable open identity. Pure codecs and rendering take explicit inputs and never inspect environment variables.

Acceptance requires round-trip tests for each format, malformed and duplicate JSON cases, generation ordering and identity coverage, complete file corruption refusal, native-input drift refusal and exact pointer tests. Native declarations are adapter validated before review and emission. Verification checks stored declarations against structurally reconstructed declarations, confirms native approvals, resolutions and native input, and invokes the supplied structural native validator; it never evaluates shell source.

Private file observation opens each absolute parent directory with no-follow descriptor traversal. The leaf must be owned by the effective user, singly linked and private. Post-read descriptor and parent-relative leaf observations must match initial size, modification and change times, ownership, permissions, device and inode; read-induced access time changes are ignored. Linked parents, hardlinks and concurrent replacement or mutation are refused.

Field names are exact and case sensitive at every object depth. Profiles are limited to 32 values matching `[a-z][a-z0-9_-]{0,31}`. Confirmations, resolutions and included IDs each have a 10000-record limit. Startup lists have at most 64 records, and nonempty routes match `[a-z][a-z0-9_-]{0,63}`.

Function declarations use `function name {` for native and portable entries. The loader installs each declaration under a success guard before removing a same-name native alias. Generation reconstruction covers only complete declarations, with no unbound header or suffix.

The synthetic canonical vector in TestGenerationIdentityInputs binds a Bash/Linux portable `demo` entry, synthetic source/native snapshots and `/synthetic/bin/printf`. Its generation ID is `dcaa3f772b19c8a10a64038ac8e57206f2def6fe865546355eb6c6061fa3292d`, complete output SHA is `7490f9a84039d6d1542dc0b755a99965c9b080d03ea41beb77d5b57b8293efd6`, and canonical manifest bytes SHA is `ba23e78fd128685b551194c62e3bc9ccf3c48575df6276c50f2e40f40fc0b7e4`.

Optional generation fields `native_source_path`, `native_source_link_target`, and `native_source_identity` bind the reviewed logical fallback source when it differs from the resolved native input. The source path is absolute; link target is the exact bounded link text; identity is decimal device and inode separated by a colon. If source binding is present, source path and identity are both required. These fields are inside canonical generation identity and omit when absent, preserving vectors without logical-source enrollment. Temporary staging inodes remain excluded.
